# Week 10.1 — E2 Git Branching and Pull Request Evidence

## Purpose
Demonstrate a feature branch, an isolated commit, and integration into the `main` branch through a GitHub pull request.

## Workflow completed
1. Created the feature branch `feature/week10-git-workflow` from `main`.
2. Added this focused documentation file on the feature branch.
3. Committed the change with a descriptive message.
4. Opened a pull request targeting `main`.
5. Merged the pull request and verified the merge in GitHub.

## What I learned
Feature branches keep work separate from the stable main branch. A pull request makes the proposed changes visible for review, and merging brings the completed work into the main branch history.
